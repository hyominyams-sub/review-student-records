# 생기부 점검

종합일람표를 학생별·영역별로 추출해 근거 중심으로 점검하고, 원본 보존 표시본과 독립된 총평본을 만든다. 반복 문구 검사는 기본적으로 제외한다.

## 시작 전

1. PDF 작업에는 `pdf:pdf` 스킬을 함께 사용하고 그 `SKILL.md`를 먼저 읽는다.
2. Drive 업로드가 요청되었거나 현재 작업 범위에 이미 포함되었다면 `google-drive:google-drive` 스킬도 읽고 사용한다.
3. `references/review-criteria.md`와 `references/validated-pdf-workflow.md`를 반드시 읽고 적용한다. 후자는 실제 5-1 종합일람표에서 결과가 검증된 PDF 분석 로직만 담고 있다.
4. 다음 설정을 프롬프트와 문서에서 우선 추출한다.
   - 입력 종합일람표 PDF
   - 적용할 기재요령·길라잡이 문서와 학년도
   - 임원 시작일과 학교별 종료일
   - 반복 문구 검사 포함 여부
   - Drive 업로드 여부와 대상 폴더
5. 설정이 없으면 다음 개인 기본값을 사용한다.
   - 반복 문구 검사: 제외
   - 학급 반장·임원 시작일: 해당 학년도의 `03.01.`
   - 임원 종료일: 기본값 없음. 학교별 학사일정·내부 자료·사용자 지시에서 확인
   - 업로드 위치: Google Drive 내 드라이브 루트
6. 시작일의 연도는 대상 학년도에 맞춘다. 종료일을 확인할 근거가 없으면 임의로 정하지 말고 주황색 확인 항목으로 남긴다. 결과가 달라지는 다른 핵심 기준을 합리적으로 확정할 수 없을 때만 사용자에게 묻는다.

## 실행 절차

### 1. 기준과 문서 구조 확정

- 안내 문서를 먼저 읽고 사용자 지시와 충돌하면 사용자 지시를 우선하되 총평에 남긴다.
- 페이지 수, 작성 기준일, 학생 수, 학생 시작·종료 페이지, 영역 열의 좌표를 파악한다.
- 연속 페이지에 걸친 학생 기록을 한 학생으로 연결한다.
- 텍스트뿐 아니라 단어별 좌표를 보존해 주석 위치의 근거로 사용한다.
- 추출 결과를 `records.json`과 사람이 읽을 수 있는 `records.txt`로 한 번 저장하고 이후 분석에서 재사용한다.
- 열 좌표, 학생 시작 표식, 머리글 높이는 현재 PDF에서 다시 확인한다. 5-1에서 검증된 좌표를 다른 크기·양식에 그대로 적용하지 않는다.

### 2. 후보 전수 탐색

- 맞춤법, 띄어쓰기, 조사·어미, 명사형 종결, 온점, 숫자·날짜, 기간, 용어 통일, 사실 확인, 기재 제한을 점검한다.
- `scripts/scan_typography.py`를 실행해 이중 띄어쓰기와 온점 후보를 얻는다. 이 결과는 확정 오류가 아니므로 원문 렌더링에서 다시 확인한다.
- 이중 띄어쓰기와 온점 탐지는 `references/validated-pdf-workflow.md`의 검증된 열 분리·줄 간격·학생 경계 조건을 유지한다.
- 문서 기준일보다 뒤의 활동일, `03.01.`이 아닌 임원 시작일, 학교 자료와 다른 종료일, 출처가 불분명한 단정·예측을 별도로 검색한다.
- 반복 문구 검사가 제외된 경우 학생 간 동일·유사 문장을 오류로 만들지 않는다.

예시:

먼저 실제 표의 본문 열 좌표를 확인하고, 산문이 들어 있는 열 범위를 반복해서 넘긴다.

```powershell
python scripts/scan_typography.py "종합일람표.pdf" `
  --output "typography-candidates.json" `
  --column-range 90:455 `
  --column-range 455:719 `
  --column-range 850:978
```

### 3. 오류 확정과 분류

- 후보를 문맥과 시각적 원본에서 재확인한다. 자동 탐지 결과를 그대로 주석 처리하지 않는다.
- 하나의 원문 구간에 같은 이유의 항목을 중복 생성하지 않는다.
- 각 항목에 고유 ID, 학생 번호·이름, 영역, 페이지, 원문, 제안, 사유, 색상, 좌표를 기록한다.
- 표기하기 어려운 전역 문제나 좌표가 불확실한 문제는 억지로 표시하지 말고 총평의 `별도 확인 사항`에 기록한다.

권장 JSON 항목:

```json
{
  "id": "R001",
  "student": "01 학생명",
  "field": "교과학습발달상황",
  "page": 2,
  "original": "있음 사회:",
  "suggestion": "있음. 사회:",
  "reason": "교과 영역 전환 전 온점 누락",
  "color": "red",
  "bbox": [100.0, 210.0, 180.0, 222.0]
}
```

### 4. 표시본 생성

- 원본 내용을 재조판하거나 덮어쓰지 말고 원본 PDF 위에 투명 형광펜 주석만 추가한다.
- 색상은 `references/review-criteria.md`의 범례를 따른다.
- 주석 설명에는 `원문 → 제안`, 사유, 학생·영역을 간결하게 넣는다.
- 이름은 반복 문구 제외 시 `{원본명}_반복문구제외_점검표시본.pdf`로 한다.
- 표시가 본문을 가리거나 다른 학생 행에 걸치지 않게 한다.

### 5. 총평본 생성

- 별도의 A4 PDF로 만든다. 필요하면 동일 내용의 Markdown도 함께 보관한다.
- 첫 페이지에 문서 범위, 학생 수, 기준일, 임원 시작일 기준, 확인된 학교별 종료일 또는 `종료일 확인 필요`, 반복 문구 포함 여부, 색상별·전체 건수를 적는다.
- 핵심 수정 사항, 사실 확인 사항, 학생별 상세 목록, 표시하기 어려운 항목, 검사 제외 범위를 포함한다.
- 개인정보를 불필요하게 복제하지 않는다.
- 이름은 `{원본명}_반복문구제외_점검총평.pdf`로 한다. 반복 문구를 검사한 경우 파일명에서 `반복문구제외`를 뺀다.

### 6. 검증

- 원본과 표시본의 페이지 수가 같은지 확인한다.
- 문제 ID가 유일하고, 추가된 주석 수가 확정 문제 수와 같은지 확인한다.
- 총평에 색상별 건수, 이중 띄어쓰기, 온점, 임원 시작일과 종료일의 근거, 반복 문구 제외 여부가 정확히 반영되었는지 확인한다.
- 모든 표시본 페이지와 총평 페이지를 렌더링한다. 전체 축소판을 훑고, 주석이 많은 페이지·페이지 경계·첫 장·마지막 장은 고해상도로 확인한다.
- 잘림, 글꼴 깨짐, 검은 영역, 빈 페이지, 좌표 이탈이 있으면 수정 후 다시 검증한다.
- `scripts/verify_review_outputs.py`로 페이지·주석·필수 문구를 재검증한다.
- 자동 탐지 수치가 맞아도 시각적 확인을 생략하지 않는다. 후보 페이지를 원본 렌더링에서 확인하고, 완성 후 표시본 전 페이지와 총평 전 페이지를 다시 렌더링한다.

예시:

```powershell
python scripts/verify_review_outputs.py `
  --source "종합일람표.pdf" `
  --marked "종합일람표_반복문구제외_점검표시본.pdf" `
  --report "종합일람표_반복문구제외_점검총평.pdf" `
  --issues-json "issues.json" `
  --require-text "반복 문구 검사는 제외"
```

### 7. Drive 업로드와 인계

- 요청된 경우 표시본과 총평본을 업로드한다.
- 업로드 결과만 믿지 말고 두 파일의 ID로 메타데이터를 다시 읽어 파일명, MIME 형식, 크기, 보기 링크를 확인한다.
- 공유 권한은 사용자가 요청하지 않으면 변경하지 않는다.
- 최종 답변에는 로컬 파일 링크, Drive 링크, 페이지·학생 수, 색상별 건수, 핵심 확인 사항, 검사 제외 범위를 짧게 정리한다.

## 완료 조건

- 표시본과 총평본이 모두 생성되고 열림
- 원본 페이지 보존, 주석 수 검증, 렌더링 확인 완료
- 이중 띄어쓰기와 온점 위치를 포함한 세부 기준 적용
- 임원 시작일 `03.01.`, 학교별 종료일과 반복 문구 설정 반영
- 요청 시 Drive 업로드 및 메타데이터 확인 완료

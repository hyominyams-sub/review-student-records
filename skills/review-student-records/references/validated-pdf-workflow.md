# 검증된 PDF 분석 워크플로우

이 문서는 2026년 5-1 종합일람표 22쪽·21명을 실제 처리하며 결과가 맞았던 로직만 정리한다. OCR, 임의의 새 추출기, 미검증 언어 모델 자동 교정은 포함하지 않는다.

## 검증 결과

- 원본 22쪽에서 학생 21명을 분리했다.
- 이중 띄어쓰기 후보 8건을 찾아 원문에서 8건 모두 확인했다.
- 교과 전환 전 온점 누락 후보 1건을 찾아 원문에서 확인했다.
- 당시 생성한 확정 문제 목록과 표시본의 추가 주석 수가 일치하는지 검증했다.
- 표시본과 총평본 전 페이지를 렌더링해 주석 위치·잘림·글꼴을 확인했다.
- Drive 업로드 후 파일명·MIME 형식·크기·보기 링크를 메타데이터로 다시 확인했다.

이 수치는 회귀 시험용 근거이며 새 문서에서 기대 건수로 사용하지 않는다.

## 1. 문서 구조를 먼저 고정하기

1. `pypdf` 또는 `pdfplumber`로 페이지 수와 페이지 크기를 확인한다.
2. `pdfplumber.extract_words(x_tolerance=1, y_tolerance=2)`로 단어와 좌표를 함께 얻는다.
3. 표 머리글과 실제 학생 본문의 시작 높이를 구분한다.
4. 영역 열의 `x0:x1`을 현재 PDF에서 측정한다.

5-1 A3 양식에서 검증된 열은 다음과 같았다.

| 영역 | x 범위 |
|---|---:|
| 교과학습발달상황 | 90:455 |
| 창의적 체험활동 | 455:719 |
| 봉사활동 | 719:850 |
| 행동특성 및 종합의견 | 850:978 |
| 출결 | 978:1132 |

페이지 크기나 표 모양이 다르면 이 좌표를 재사용하지 않는다. 현재 PDF에서 열 경계를 다시 측정한 뒤 `scan_typography.py --column-range`에 넘긴다. 열을 분리하지 않으면 옆 열의 학생 번호나 머리글 간격이 이중 띄어쓰기로 잘못 잡혔다.

## 2. 학생 경계를 정확히 나누기

검증된 양식에서는 다음 세 단서를 함께 사용했다.

- 교과 열의 `국어:` 표식
- 왼쪽 학생 번호 열
- 왼쪽 학생 이름 열

`국어:`의 세로 좌표와 가장 가까운 번호·이름을 학생 시작점으로 묶는다. 학생 번호를 정렬한 뒤 누락·중복·역순이 없는지 확인한다.

한 학생이 여러 페이지에 걸치면 다음 학생 시작 페이지까지 연결한다. 다음 학생과 같은 페이지에서 끝날 때 추출 하단을 `다음 학생 start_y - 0.5`로 잡아 다음 학생의 첫 줄이 섞이지 않게 한다. 이어지는 페이지의 본문 시작 높이와 페이지 하단 여백도 현재 양식에서 확인한다. 5-1에서는 이어지는 페이지 상단 `148`, 하단 `page_height - 45`를 사용했다.

추출 후 다음을 반드시 대조한다.

- 발견한 학생 수와 실제 명렬 수
- 첫 학생과 마지막 학생 번호
- 학생별 시작·종료 페이지
- 다음 학생 문장이 이전 학생 `records.json`에 섞이지 않았는지

## 3. 원문과 분석용 텍스트를 분리하기

- 분석용 텍스트에서는 BOM(`U+FEFF`)을 제거하고 연속 공백·빈 줄을 정리한다.
- 이중 띄어쓰기와 주석 좌표 검사는 정리된 텍스트가 아니라 원래 단어 좌표로 수행한다.
- 문구 검색용 정규화는 한글·영문·숫자를 이어 붙이는 용도로만 쓴다.
- 실제 수정 위치는 정규화 문자열이 아니라 매핑된 원본 단어 묶음에서 구한다.
- 한 단어 내부 표기와 두 단어 사이 표기를 구분해야 할 항목은 정확한 토큰 조건으로 찾는다. 정규화 검색만 사용하면 비슷한 다른 표현까지 잡힐 수 있다.

## 4. 이중 띄어쓰기 탐지

5-1에서 다음 로직이 8건을 정확히 찾았다.

1. 산문이 있는 교과·창체·행동특성 열만 각각 분리한다.
2. 단어의 `top` 차이가 2.0 이하인 것끼리 같은 줄로 묶는다.
3. 같은 줄의 인접 단어 간격을 계산한다.
4. `1.0 <= 간격 <= 15.0`인 값의 중앙값을 그 줄의 일반 간격으로 삼는다.
5. 실제 간격이 `6.8` 이상이면서 일반 간격의 `1.65배` 이상일 때 후보로 만든다.
6. 표 열 경계, 양쪽 정렬, 들여쓰기는 원본 렌더링에서 제외한다.

위 수치는 같은 계열의 A3 양식에서 검증되었다. 다른 양식에서는 자동 확정 기준으로 쓰지 말고 후보를 만든 뒤 원본 화면에서 확인한다.

## 5. 온점과 문장부호 탐지

### 교과 전환 전 온점

- 교과 열에서 `사회:`, `도덕:`, `수학:`, `과학:`, `실과:`, `체육:`, `음악:`, `미술:`, `영어:`를 찾는다.
- 바로 앞 단어가 `.`, `!`, `?`로 끝나지 않으면 후보로 만든다.
- 앞 단어가 머리글이거나 본문 시작 높이보다 위이면 제외한다.
- 앞 단어와 교과명이 같은 학생에게 속할 때만 확정한다.

이 조건으로 `있음 사회:` 1건을 찾아 `있음. 사회:`로 제안했다. 같은 학생 확인이 없으면 페이지 경계나 다음 학생의 첫 교과명을 잘못 잡을 수 있다.

### 분리된 온점·쉼표

- 단독 `.` 또는 `,` 토큰을 찾는다.
- 앞 단어와 같은 줄이며 간격이 1.2 미만이면 정상 결합으로 제외한다.
- 그 밖의 경우에만 문장부호 앞 공백 후보로 만든다.

## 6. 후보를 확정 문제로 바꾸기

- 자동 결과는 모두 후보로 취급한다.
- 원문 문맥과 렌더링된 페이지에서 같은 위치를 확인한 뒤 문제 목록에 넣는다.
- 한 구간에 같은 사유를 두 번 넣지 않는다.
- 머리글, 페이지 번호, 열 경계, 다음 학생의 문장은 제외한다.
- 반복 문구 검사가 꺼져 있으면 동일·유사 문장을 문제로 생성하지 않는다.
- 확정 항목마다 고유 ID, 학생, 영역, 페이지, 원문, 제안, 사유, 색상, 사각형 좌표를 저장한다.

## 7. 형광펜 좌표 만들기

`pdfplumber`의 좌표는 위쪽 기준이고 PDF 주석 좌표는 아래쪽 기준이다. 검증된 변환은 다음과 같다.

- `y_top = page_height - top`
- `y_bottom = page_height - bottom`

여러 줄 문구는 줄별 사각형과 쿼드 포인트를 만든다. 원본 페이지를 다시 조판하지 않고 원본 PDF에 투명도 0.35의 Highlight 주석을 추가한다. 회전 정보는 콘텐츠에 반영한 뒤 페이지를 복사했다.

## 8. 검증 순서

1. 문제 ID의 유일성을 확인한다.
2. `원본 페이지 수 == 표시본 페이지 수`인지 확인한다.
3. `표시본 주석 수 - 원본 기존 주석 수 == 확정 문제 수`인지 확인한다.
4. 총평의 색상별 합계가 전체 문제 수와 같은지 확인한다.
5. 총평에 이중 띄어쓰기·온점·임원 시작일·학교별 종료일·반복 문구 제외 여부가 들어갔는지 확인한다.
6. 표시본과 총평본 전 페이지를 PNG로 렌더링한다.
7. 전체 페이지를 훑고, 첫 장·마지막 장·학생 경계·주석이 많은 페이지를 확대 확인한다.
8. 잘림, 글꼴 깨짐, 검은 영역, 빈 페이지, 다른 학생 행을 덮은 주석이 있으면 수정 후 같은 검증을 반복한다.

## 정확도와 처리 효율을 함께 지키는 순서

이번 작업에서 검증된 순서는 다음과 같다.

1. 페이지·열·학생 경계를 먼저 확정한다.
2. `records.json`과 `records.txt`를 한 번 생성해 이후 규칙 검사의 공통 입력으로 사용한다.
3. 전체 텍스트 규칙과 좌표 기반 띄어쓰기·온점 규칙을 분리한다.
4. 자동 후보를 모은 뒤 원본 렌더링에서 확정한다.
5. 확정된 단일 `issues.json`에서 표시본과 총평본을 함께 만든다.
6. 마지막에 주석 수·총평 건수·렌더링을 교차검증한다.

이 순서를 바꾸어 표시본과 총평본을 따로 집계하면 건수가 어긋날 수 있다. 확인되지 않은 OCR이나 새 임계값을 중간에 추가하지 않는다.

# 9. 좌표계와 임계값: 실측으로 확인한 사실

아래는 회전이 걸린 실제 종합일람표(A3 세로 용지 + `/Rotate 90`, 20쪽·22명)와
같은 형식으로 재현한 회전 없는 문서에서 **직접 재보고 고친** 내용이다.
그럴듯한 추측으로 잘못 적어 두었다가 실패한 항목이 있어 근거와 함께 남긴다.

## 9.1 PyMuPDF는 텍스트도 도형도 '비회전' 좌표를 준다

| 대상 | 좌표계 |
|---|---|
| `page.rect` | 회전 **후** (예: `1191 x 842`) |
| `page.get_text("words")` | 회전 **전** (예: x≤842, y≤1191) |
| `page.get_drawings()` | 회전 **전** |
| 주석(annotation) 삽입 | 회전 **전** |

즉 `get_text`만 회전 후 좌표를 준다고 생각하면 안 된다. 셋 다 비회전이다.
확인 방법: 낱말 하나의 bbox를 그대로 `add_highlight_annot`에 넣고 렌더링해 보면
정확히 그 글자에 칠해진다. 회전 행렬을 곱해 넣으면 엉뚱한 곳에 칠해진다.

행·열을 사람이 보는 대로 다루려면 **낱말과 도형을 모두** `page.rotation_matrix`로
같이 보내 놓고 판단하고, 주석을 만들 때만 원래(비회전) 좌표로 되돌린다.
`extract_records.py`의 `visual_words()`가 이 방식이며, 낱말마다 비회전 사각형을
같이 들고 다녀서 `records.json`의 `bbox`는 곧바로 주석에 쓸 수 있다.

## 9.2 열 경계는 '머리글 아래 행'에서 재야 한다

세로선 길이를 페이지 전체에서 재고 최댓값 대비 비율로 거르면 두 군데서 깨진다.

- 병합된 그룹(창의적 체험활동, 출결 상황)의 안쪽 구분선은 그룹 선 아래에서 시작하므로
  머리글 전체 높이를 기준으로 하면 걸러진다.
- 마지막 쪽처럼 표 본문이 짧으면 바깥 테두리만 길게 남아, 안쪽 열 선이 전부 걸러진다.

그래서 **머리글의 아래 행 구간에서만** 세로선 겹침 길이를 재고, 그 구간의 80% 이상을
지나는 선만 열 경계로 본다. 이 방법으로 회전 문서와 비회전 문서 모두에서
13개 열이 동일하게 나왔다.

가로선은 반대로 페이지 전체 기준이 잘 맞는다. 머리글 중간선은 표 폭의 절반쯤만
차지하므로 자동으로 걸러지고, 남는 첫 번째 선이 곧 머리글 하단이다.

## 9.3 이중 띄어쓰기 임계값은 글자 크기에 딸려 간다

고정 pt 값(예전 기본값 `6.8`)은 8pt 본문에서 **이중 공백을 하나도 잡지 못한다.**
8pt 굴림에서 공백 한 칸은 약 2.2pt라 두 칸이어도 4.4pt에 그치기 때문이다.

실측:

| 문서 | `--min-gap 6.8` | `--min-gap auto` |
|---|---:|---:|
| 시험지(정답 이중 공백 2 + 온점 누락 1) | 1건 (이중 공백 0/2) | 3건 (3/3) |
| 실제 20쪽 종합일람표 | 0건 | 4건 |

실제 문서에서 나온 4건은 간격이 각각 기준 대비 1.93~1.98배였다.
정확히 두 배에 가까운 값은 진짜 이중 공백의 특징이다.

그래서 `--min-gap` 기본값을 `auto`로 두고, 판정은 그 줄·그 열의 **중앙값 대비 비율**
(`--min-ratio`, 기본 1.65)에 맡긴다. `--auto-gap-floor`(기본 2.0pt)는 잡음 하한일 뿐이다.
양쪽 정렬된 문서라면 이 방법을 쓰지 말고 총평의 `별도 확인 사항`으로 넘긴다.

## 9.4 주석 수를 셀 때 Popup을 빼야 한다

메모가 달린 하이라이트는 `/Popup` 주석을 하나 더 만든다.
`/Annots` 항목을 그냥 세면 문제 수의 정확히 두 배가 나와 검증이 실패한다.
`verify_review_outputs.py`는 `/Subtype`이 `/Popup`인 것을 빼고 센다.

## 9.5 종결어미는 `습니다`가 아니라 `니다`로 찾는다

`뛰어납니다`, `참여합니다`는 `ㅂ니다` 활용이라 `습니다`가 들어 있지 않다.
`습니다`만 찾으면 명사형 종결 위반을 **하나도 못 잡는 일이 실제로 있었다.**
`니다.` 로 찾아야 한다.

## 9.6 띄어쓰기 규칙은 공백을 지운 문자열에 쓰면 안 된다

줄바꿈을 넘어 문구를 찾으려고 공백을 지운 문자열을 만들면 편하지만,
그 문자열에 `할수` 같은 띄어쓰기 규칙을 걸면 **정상인 `파악할 수`도 걸린다.**
띄어쓰기 판정은 반드시 낱말 하나 안에서만 한다.
